# AI4SciWatch

A directory of AI tools for science: assistants, review, publishing, and benchmarks.

A static SvelteKit site, fully prerendered for GitHub Pages. Each category is its own page, with entries grouped into sections. Search runs in the browser.

The same directory is published as Markdown at `/llms.txt`, with a short guide to contributing. It links to the site, and the contribute link and guide point to the GitHub repo the site is built from. GitHub Actions provides both at build time; local builds leave them out.

## Editing

All content is in `src/lib/directory.ts`; the title and description are in `src/lib/site.ts`.

- **Categories** each have a title and ordered subcategories. Assistants is at `/`; the others are at `/<category>`.
- **Entries** have a `name`, `url`, `category`, `sub` (where the category has subcategories) and a one-line `blurb`. Optional `notes` show on hover; `reviewed` and `sources` record when and where an entry was last checked.
- **Organisations** are a registry referenced by `organisationIds`; use `author` for individuals. They are searchable but not shown.

Icons are self-hosted in `static/icons/`, so the site makes no third-party requests. After changing entries, run `npm run icons` (any OS; resizes with `sharp`) to refetch them and rewrite `src/lib/icons.json`. Entries without a usable icon get a monogram.

## Development

Requires Node 24.

```sh
npm ci
npm run dev
npm run validate   # type check and format check
```

## Deployment

Pushing to `main` runs `.github/workflows/pages.yml`, which validates, builds for the site's Pages address and publishes it. Set the repo's Pages source to "GitHub Actions" once.

GitHub Pages can't set response headers, so the Content Security Policy is a `<meta>` tag generated by SvelteKit.
